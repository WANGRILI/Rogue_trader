# 参数化执行计划

[中文](execution-plans.md) · [English](execution-plans.en.md)

RogueTrader 可在最终投研决策之后追加一次快速模型调用，由非投票角色“执行规划器”将自然语言决策翻译为 `执行计划.json`。规划器不得修改投资组合经理的评级。

## 第一版边界

- 只支持现货（`spot`）和模拟执行（`paper`）。
- `auto_submit` 固定为 `false`，没有交易所提交代码。
- 不支持杠杆、保证金、衍生品和现货做空。
- 价格条件只能使用最终决策中已经明确出现的数值，不得补造价位。
- 计划生成失败不会把已完成的投研结果改成失败。

## 两阶段输出

```text
最终决策.json
      ↓ 执行规划器 + 严格协议校验
执行计划.json（每日正式交付结果，参数化，不可下单）
      ↓ 可选：未来接入模拟器时绑定账户状态
执行实例.json（确定数量，仅供模拟，不是每日任务依赖）
```

`执行计划.json` 可包含多个场景，每个场景可包含多条有顺序的委托：

- 场景：优先级、互斥组、立即、最新价格或人工确认条件。
- 委托：买卖方向、建仓/加仓/减仓/退出意图、市价/限价/止损类型、执行顺序。
- 数量：按当前持仓比例、可用现金比例或固定数量表达。
- 风险：可附带止盈、止损、最大持仓比例和单笔现金比例。

## X 参数：每日无需输入

每日任务不要求人工提供账户数据。委托直接携带可读的 `size_expression`：

- `0.30 × X_POSITION`：执行时卖出当前持仓的 30%。
- `0.10 × X_CASH`：执行时使用可用资金的 10% 买入。
- 固定数量只在原始决策明确给出绝对数量时使用。

`X_POSITION` 和 `X_CASH` 是计划中的合法参数，不是缺失数据。只要 `执行计划.json` 已生成，当日分析任务就是完整的。

下面 3 个值只在未来需要把公式换算成确定数量时，由模拟器或账户适配器自动提供；不属于每日人工输入：

| 参数 | 含义 |
|---|---|
| `position_qty` | 当前现货持仓数量 |
| `available_cash` | 当前可用计价货币 |
| `last_price` | 最新价格 |

`open_buy_qty` 和 `open_sell_qty` 是可选的未成交聚合数量，默认为零。数值绑定工具不需要完整账户、历史订单、用户身份或 API 密钥，也不会影响每日计划生成。

“日线收盘跌破”、指标信号或新闻事件不能由 `last_price` 代替。第一版会把它们保留为 `manual_confirmation`，委托状态为 `waiting_confirmation`，避免为了自动化而篡改原决策条件。

数量精度和最小委托金额是静态模拟市场规则，不属于实时状态。

## 可选数值绑定

```bash
ops/bind-execution-plan <运行结果目录> \
  --position-qty 1 \
  --available-cash 10000 \
  --last-price 100
```

命令只写入 `执行实例.json`，不连接券商或交易所。执行实例可能处于：

- `ready`：当前有首组委托可交给模拟器。
- `waiting`：尚未命中价格条件。
- `no_action`：场景命中但不需要委托。
- `blocked`：现金、持仓或风险上限校验失败。
- `expired`：计划超过有效期。

有 `after_order_id` 的后续委托不会与前置委托同时就绪；它在执行实例中保持 `waiting_dependency`，由后续模拟器在前置委托成交后激活。

## 跨日策略承接

同一标的的新计划会自动读取同一运行环境中最近一份已完成计划，并写入：

- `previous_plan_id`：上一份计划 ID。
- `continuity_action`：`retain`、`amend` 或 `replace`；首份计划为 `baseline`。
- `change_summary`：明确旧指令哪些延续、撤销或替换。

规划器不得假定上一日委托已经成交。它只承接策略和指令关系，因此不需要账户状态，也不会把开发计划串到生产计划。

每份新计划都是同一标的当前唯一有效的完整快照，不是对旧计划追加几条指令。仍然有效的旧指令必须在新计划中再次出现；未被带入的旧指令视为撤销或替换。旧文件继续保留，仅用于审计和回看。

## 历史计划回填与委托汇总

已有完整报告不需要重跑多智能体分析。回填器直接读取正式 `每日决策.csv` 对应的 `最终决策.json`，按“正式/开发链路 × 标的 × 分析日期”顺序调用执行规划器，使后一日计划能够承接前一日计划。迁移前的 `legacy` 正式历史会自然衔接到后续 `prod`，而开发结果始终独立。

默认命令只预演，不调用模型、不写文件：

```bash
ops/backfill-execution-plans
```

实际生成必须显式限制本次最多新增的计划数：

```bash
ops/backfill-execution-plans --apply --max-plans 10
```

可用 `--date-from`、`--date-to` 和重复的 `--ticker` 缩小范围。默认只处理决策主表中已经选定的正式结果；`--all-completed` 才会包含开发或手动候选。早期结果中没有时区的生成时间按项目历史约定解释为 `Asia/Shanghai`。某日生成失败时，同一链路和标的的后续日期会停止承接，其他标的不受影响。该命令不发送飞书消息，也不重新运行付费分析。

批处理默认单次请求超时 60 秒、SDK 最多重试 1 次，可通过 `--request-timeout` 和 `--max-retries` 在受限范围内调整。已经成功落盘的计划不会在续跑时再次调用模型。使用日期过滤从断点续跑时，程序会自动装载同一链路紧邻的前序计划；前序计划尚未生成或既有谱系不连续时会安全停止，不会悄悄创建新的基线。长批次可加 `--summary-only`，只输出汇总和首个错误。

隔离开发时，可以先把需要的完整结果复制到开发结果区，再用 `--official-csv /path/to/每日决策.csv` 只读引用正式主表。执行计划和委托 CSV 仍只写入 `--results-root` 指定的开发目录，不会修改正式源目录。

计划会同时展开到 `my_results/汇总/参数化委托.csv`：一条委托占一行，无委托场景保留一条 `no_order` 行。`plan_id`、`scenario_id`、`order_id` 和 `order_event_id` 保留从决策到场景、再到委托的完整关系；重复运行只补缺失记录。未来每日发布也使用同一个 CSV sink 自动追加新计划。

委托明细表可以直接进入时点安全的 OHLCV 回测；时间口径、成交假设与证据边界见[参数化委托回测](execution-backtest.md)。

## 飞书指令通知

飞书群通知开启时，一个带有有效 `执行计划.json` 的新结果只发送一张合并卡片：参数化执行指令在前，完整决策摘要在后。

执行指令按情境合并编号，逐组展示“当前状态、含义、触发条件和精确委托”。例如“立即执行意图”“现在就可挂出的 GTC 限价单”“等待条件确认”和“等待复合条件”，并明确等待类指令不是同时挂单。

卡片由本地程序直接读取并严格校验 JSON 后生成，不调用模型。整张卡片共用一个 `feishu` 投递状态，失败时只重试一次合并投递，不重新运行付费分析；没有执行计划的旧结果仍发送原有决策卡片。

## 开启方式

控制面板中的“参数化执行计划”是独立开关。手动运行也可使用：

```bash
uv run --frozen python my_scripts/roguetrader0.py \
  --ticker BTC-USD \
  --date 2026-09-13 \
  --execution-plan \
  --no-debug
```

开启后会增加一次快速模型调用。可使用 `--no-execution-plan` 或环境变量 `ROGUETRADER_EXECUTION_PLAN_ENABLED=0` 关闭。
