# 每日任务健康审计

[中文](daily-health-monitor.md) · [English](daily-health-monitor.en.md)

健康审计独立检查每日分析与发布链路，不修改分析流程，也不会自动重新执行付费分析。

## 检查时间

健康审计以控制面板配置的每日执行时间为基准：

| 检查 | 相对计划时间 | 当前 05:00 计划 |
|------|--------------|------------------|
| 首次检查 | +15 分钟 | 05:15 |
| 第一次复查 | +30 分钟 | 05:30 |
| 第二次复查 | +45 分钟 | 05:45 |
| 第三次复查及最终裁决 | +60 分钟 | 06:00 |

如果完整链路在任意一次检查时已经成功，当日审计立即结束，不发送告警。若到最终裁决仍有异常，系统向已经启用并通过测试的飞书群机器人发送一条聚合失败卡片。

为避免部署或开发调试产生误报，如果服务在当天最终截止时间之后首次启动，而且没有发现当天的调度记录、运行中任务或结果目录，系统会把当天标记为“冷启动跳过”，从下一次计划任务开始审计。若已经存在失败记录或残缺结果，则仍会如实告警。

检查结果保存在当前运行环境的 `control-panel/daily-health.json`，服务重启后不会重复发送同一天的成功告警。

## 检测范围

审计按启用标的分别检查：

1. `runs.json` 中是否存在当天计划任务，以及分析进程是否成功退出；
2. 当天结果目录是否符合 `<启动时间>__asof-<分析日期>__<环境>__<触发>-a<次数>__<标的>` 规则；
3. `运行索引.json` 和 `最终决策.json` 是否一致；
4. 索引声明的报告、状态、配置、终端日志和阶段报告是否全部存在；
5. 决策主表、参数化委托明细表与本地消息是否成功；
6. 已启用的飞书群消息是否成功；
7. 已启用的飞书电子表格是否成功；
8. 发布轮询线程是否正常运行。

多个标的的失败原因会合并到同一条告警中，不会为每个标的重复轰炸群聊。

## 失败分类

| 类别 | 含义 |
|------|------|
| `task_not_started` | 到检查时间仍没有任务或结果记录 |
| `analysis_running` / `analysis_timeout` | 分析仍在执行，或到最终截止仍未结束 |
| `analysis_failed` | 分析进程以非零退出码结束 |
| `result_missing` / `result_incomplete` / `result_invalid` | 结果目录、完成标记或阶段文件不完整 |
| `publisher_unavailable` | 发布器线程没有运行 |
| `csv_*` / `execution_csv_*` / `local_message_*` | 本地发布边界尚未完成或失败 |
| `feishu_*` | 飞书群消息配置或投递异常 |
| `feishu_sheet_*` | 飞书表格配置或同步异常 |

控制面板只展示安全的错误分类和退出码，不返回结果正文、凭据、Webhook、App Secret 或本地绝对路径。

## 重试边界

- 三次复查只重新读取运行状态，并唤醒已有发布任务。
- 飞书消息和表格沿用各自的幂等键及退避策略。
- 分析失败、结果缺失或分析超时不会自动启动新的模型任务。
- 告警通过现有飞书群机器人发送；如果飞书群通道本身不可用，失败状态仍会写入本地并显示在控制面板，但无法通过同一故障通道送达远端。

这个边界避免瞬时状态造成过早告警，也避免无人值守时重复产生模型费用。
