# 运行结果协议

[中文](run-results.md) · [English](run-results.en.md)

RogueTrader 使用单层、可解析的 v2 目录名，同时表达分析日期和实际运行时间：

```text
20260913_115207__asof-20260913__prod__recovery-a02__BTC_USD
└─实际启动时间      └─请求分析日期   └环境  └触发及尝试次数  └标的
```

运行环境为 `prod`、`dev` 或历史未知的 `legacy`；触发类型为 `scheduled`、`recovery`、`manual` 或历史未知的 `unknown`。尝试次数以“分析日期 + 标的 + 环境”为一组，从 `a01` 递增。

`asof` 当前表示传给分析引擎的请求分析日期，不宣称所有外部数据源都严格冻结在某个精确时刻。精确的计划时间、启动时间和完成时间位于 `运行清单.json`。

## 生命周期文件

- 任务开始即原子写入 `运行清单.json`，状态为 `running`。
- 失败或中断会更新清单状态，即使尚未产生任何分析正文也能被健康监控识别。
- 完整输出写入后才生成 `运行索引.json`；发布器将它作为成功完成标记。
- `publication_event_id` 固化在清单中，与目录名称解耦，后续迁移不会制造新的发布事件。
- 开启执行规划后可额外生成 `执行计划.json`；失败只记录 `execution_plan_status`，不会破坏已完成的分析结果。

`执行计划.json` 是可选新文件，旧版运行器和发布器会忽略它。详细协议见[参数化执行计划](execution-plans.md)。

生产定时和失败恢复结果可参与正式结果选择。开发、手动和无法确认来源的历史结果默认只作为候选；`official` 等可变状态保存在元数据和发布状态库中，不进入目录名。

## 历史迁移

先执行只读预演：

```bash
ops/migrate-run-layout --results-root /path/to/my_results
```

确认生产控制面板和分析任务已经停止后才能应用：

```bash
ops/migrate-run-layout --apply --results-root /path/to/my_results
```

迁移会保存旧名到新名的私有清单、备份发布状态库、校验每个目录的原文件内容，并保持 CSV 不变。若上线前验证失败，可立即使用相同参数加 `--rollback` 恢复旧目录和数据库。

旧调度遗留在 `运行结果/` 根目录的日志文件会原样归档到 `my_results/历史日志/`，避免与正式运行目录混排；回滚时会恢复原位置。

v1 目录仍可被读取。旧版本回滚期间产生的 v1 结果也可以正常执行，重新切回 v2 后再通过迁移工具规范化。
