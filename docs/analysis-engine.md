# 分析引擎

## 目标

RogueTrader 的分析引擎用于组织多来源数据、不同研究立场和风险偏好，最终形成一个结构化交易判断。它提供研究建议，不直接下单。

## 工作流

```text
输入：标的 + 分析日期
        ↓
分析师团队：市场、社交、新闻、基本面、链上
        ↓
多头研究员 ↔ 空头研究员
        ↓
研究经理裁决
        ↓
交易员生成交易计划
        ↓
激进、保守、中立风控辩论
        ↓
投资组合经理给出最终决策
```

最终动作限定为：`BUY`、`OVERWEIGHT`、`HOLD`、`UNDERWEIGHT` 或 `SELL`。

## 角色

| 角色 | 主要职责 |
|------|----------|
| 市场分析师 | 价格、成交量、趋势和技术指标 |
| 社交分析师 | 社区讨论、情绪和热度变化 |
| 新闻分析师 | 市场新闻、宏观事件和公司事件 |
| 基本面分析师 | 财务、估值和经营数据 |
| 链上分析师 | 供应、鲸鱼、DeFi、稳定币、挖矿和衍生品指标 |
| 多头/空头研究员 | 从相反立场构建并检验投资论点 |
| 研究经理 | 综合证据并裁决研究辩论 |
| 交易员 | 将研究结论转化为方向、仓位和条件计划 |
| 风控三角色 | 从激进、保守和中立角度审视风险 |
| 投资组合经理 | 输出最终决策和风险约束 |

## 链上研究

链上能力包括：

- 市值、供应量、FDV、ATH/ATL 和多周期价格变化；
- 交易所成交量分布与集中度代理指标；
- 公链或协议 TVL、稳定币供应变化；
- BTC 算力、难度、活跃度和矿工收入；
- Pi Cycle、NVT、资金费率、CME 缺口和恐惧贪婪指数。

免费公开数据通常适合研究和当前观察，但不一定满足严格 point-in-time 历史回测要求。

## 模型分工

系统将角色分为快速推理和深度推理两类：

- 分析师、研究员、交易员和风控辩手通常使用快速模型；
- 研究经理与投资组合经理通常使用深度模型。

可以通过 `configs/agents.yaml` 为单个角色覆盖模型、身份、关注重点和表达风格。未设置的字段回退到代码默认值。

## 记忆与反思

研究和管理角色可以使用 BM25 记忆检索相似历史案例。得到真实收益后，可通过 `reflect_and_remember()` 写入经验，用于后续类似场景。

记忆不会替代实时数据，也不能消除模型偏差。历史学习结果需要结合数据时间边界和真实交易条件解释。

## 结构化输出

完整运行会生成：

- `运行索引.json`：完成标记与文件索引；
- `最终决策.json`：标的、日期、动作和决策正文；
- `报告.md`：完整研究报告；
- `状态.json`：最终图状态；
- `运行配置.json`：本次运行参数；
- `分段报告/`：各阶段报告。

结果发布器只在索引和决策文件通过一致性校验后消费该运行。
